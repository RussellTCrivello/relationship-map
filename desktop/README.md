# النسخة المكتبية (Windows)

برنامج مستقل يُفتح بنقرتين: لا يحتاج إلى قاعدة بيانات ولا إلى إنترنت. تُحفظ البيانات في ملف واحد على جهازك
(`%APPDATA%\RelationshipMap\data\relationship-map.json`) مع نسخة احتياطية تلقائية بجانبه (`.bak`).

## بناء البرنامج (مرة واحدة، على جهاز Windows)

1. ثبّت **Node.js LTS** من https://nodejs.org
2. افتح PowerShell داخل مجلد المشروع ثم:

```
git pull
cd desktop
npm install
npm run dist
```

3. ستجد الملفات في `desktop\dist\`:
   - `RelationshipMap Setup 1.0.0.exe` — مثبّت: نقرتان فيُثبّت البرنامج وتظهر أيقونته على سطح المكتب.
   - `RelationshipMap-Portable.exe` — نسخة محمولة تعمل بنقرتين دون تثبيت (يمكن وضعها على فلاشة).

لتجربة البرنامج دون بناء مثبّت: `npm start`.

> عند أول تشغيل قد تعرض Windows تحذير «SmartScreen» لأن البرنامج غير موقّع رقميًا:
> اضغط **مزيد من المعلومات** ثم **تشغيل على أي حال**.
> إن ظهر خطأ «Cannot create symbolic link» أثناء `npm run dist` فشغّل PowerShell كمسؤول أو فعّل «وضع المطوّر» في إعدادات Windows.

## كلمة المرور

- عند أول تشغيل تظهر نافذة بكلمة مرور المدير الأولية (وتُنسخ إلى الحافظة). اسم المستخدم: `admin`.
- غيّرها بعد الدخول من أيقونة الحساب.
- نسيتها؟ من القائمة: **ملف ← إعادة تعيين كلمة مرور المدير**. بياناتك لا تتأثر.

## النسخ الاحتياطي

- **ملف ← حفظ نسخة احتياطية…** يحفظ ملف بيانات العلاقات في المكان الذي تختاره؛ المناطق وخرائطها المحفوظة في المتصفح لا يتضمنها هذا الملف. صدّرها أيضًا من إعدادات الخريطة عبر «تصدير جميع المناطق».
- **ملف ← فتح مجلد البيانات** يفتح مجلد الملف المذكور أعلاه.
- يمكنك أيضًا التصدير والاستيراد من قائمة «الأدوات» داخل البرنامج.

## كيف يعمل

يشغّل البرنامج الخادم نفسه (`server/`) داخل نافذة Electron على العنوان `127.0.0.1` فقط (المنفذ الثابت 47831)،
إذا كان المنفذ مستخدمًا يعرض البرنامج خطأً بدل الانتقال إلى منفذ آخر، حتى تبقى بيانات المتصفح والمناطق على نفس الأصل بعد إعادة التشغيل. لذلك لا يصل إليه أي جهاز آخر. التخزين في ملف بدل PostgreSQL (`DB_ENGINE=file`، انظر `server/file-pool.js`).

### الخريطة النقطية المحمّلة دون اتصال

تُحوَّل قاعدة بلاطات الخريطة (`offline_map/gaza_copernicus_osm_z11-z17.mbtiles`) أثناء التحضير (`npm run prepare-app`) إلى ملف حزمة ثنائي واحد (`offline_map/gaza.tilepack`) عبر `scripts/build-tilepack.js`، ويُشحن مع البرنامج عبر `extraResources` خارج أرشيف `app.asar` (يُقرأ عبر `process.resourcesPath/offline_map/gaza.tilepack` أو المتغير `OFFLINE_TILES_FILE`) دون الحاجة إلى أي إضافات SQLite أصلية في بيئة التشغيل.


> إصدارات سطح المكتب السابقة كانت قد تستخدم منفذًا بديلًا عند انشغال 47831. بيانات المناطق المخزنة على ذلك المنفذ تبقى في ملف المتصفح القديم ولا تنتقل تلقائيًا إلى الأصل الثابت. إن توفرت النسخة السابقة، صدّر المناطق منها واستوردها في النسخة الجديدة؛ لا تحذف ملف المتصفح القديم قبل التحقق.
